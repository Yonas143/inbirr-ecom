# Security reporting

Do not post credentials, customer data or working exploit details in public issues. Use GitHub's private vulnerability reporting feature for this repository when enabled. If unavailable, open an issue containing only a request for a private reporting channel.

This is an early starter, not an audited security product. Store owners must configure infrastructure permissions, backups, email and payment providers, HTTPS, key expiry and access scopes. Never use development schema push, demo seeding or integration tests on a production database.
